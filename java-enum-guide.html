The enum field guide

Enums look like a list of constants but compile into a full class hierarchy — each constant is a real, singleton object. This guide walks through that mental model with diagrams, then covers every method and pattern that comes up in interviews.

1

What is an Enum?

An enum represents a fixed, closed set of constants. Instead of a loose String that can hold any value, an enum restricts a variable to only the values you've declared.

before
String day = "MONDAY";
after
Day day = Day.MONDAY;
2

Why do we use Enum?

no enum
String status = "DONE";
status = "ABC";  // allowed
status = "XYZ";  // allowed
with enum
Status s = Status.DONE;
s = Status.NEW;   // allowed
s = Status.ABC;   // compile error

The compiler enforces the rule — no runtime surprises from a typo'd string.

3

Declaring & Using an Enum

Day.java
enum Day{
    MONDAY,
    TUESDAY,
    WEDNESDAY
}
Main.java
Day d = Day.MONDAY;
System.out.println(d);
MONDAY
5

Enum Constants Are Objects

This is the single most important interview point. When Java compiles the enum above, it silently generates a full class:

what the compiler builds
public final class Day extends Enum<Day> {
    public static final Day MONDAY;
    public static final Day TUESDAY;
    public static final Day WEDNESDAY;
}
6

Variable Stores a Reference

A variable of enum type doesn't hold the constant — it points to it. Reassigning the variable moves the arrow; it never changes the object underneath.

7

Enum Constructors

Enums can have constructors — they run once per constant, when the enum class is first loaded.

Day.java
enum Day{
    MONDAY, TUESDAY, WEDNESDAY;

    Day(){
        System.out.println("Constructor");
    }
}
Constructor Constructor Constructor
⚠

Cannot be public — only private or package-private. A public Day(){} is a compile error, because Java must forbid new Day() from outside; constants are the only instances allowed to exist.

9

Fields Inside Enum — Accessed via Getters

Give each constant its own data by passing arguments into the constructor. The fields are typically private, so you read them back through getter methods — exactly like any other object.

Day.java
enum Day{

    MONDAY(1, "Start of week"),
    TUESDAY(2, "Second day"),
    WEDNESDAY(3, "Middle of week");

    private int dayNumber;
    private String description;

    Day(int dayNumber, String description){
        this.dayNumber = dayNumber;
        this.description = description;
    }

    public int getDayNumber(){ return dayNumber; }
    public String getDescription(){ return description; }
}

Reading the values

Main.java
Day day = Day.MONDAY;
System.out.println(day.getDayNumber());
System.out.println(day.getDescription());
1 Start of week
✕

Direct field access fails because the fields are private: day.dayNumber and day.description are both compile errors. You must go through getDayNumber() / getDescription().

CallReturns
Day.TUESDAY.getDayNumber()2
Day.TUESDAY.getDescription()Second day

The Built-in Toolkit

Every enum you write automatically inherits these — no extra code needed.

values() · returns every constant

for(Day d : Day.values()){

}
MONDAY TUESDAY WEDNESDAY

ordinal() · position in declaration order

⚠

Avoid using ordinal() for business logic — reordering the constants silently reshuffles every value.

valid
Day d = Day.valueOf("MONDAY");

-2

== vs equals()

Both work identically for enums, because only one instance of each constant ever exists. Interviewers expect: prefer == — it's a cheap reference check and can never throw a NullPointerException.

Day d = Day.MONDAY;
d == Day.MONDAY        // true
d.equals(Day.MONDAY)   // true

switch on an enum

switch(day){
    case MONDAY:
        System.out.println("Start");
        break;
    case TUESDAY:
        System.out.println("Second");
        break;
}
18

Enum Implements Interfaces

allowed
interface Test{ void show(); }

enum Day implements Test{
    MONDAY;
    public void show(){ System.out.println("Hello"); }
}

But an enum can never extend another class — every enum already implicitly extends java.lang.Enum, and Java has no multiple inheritance of classes.

illegal
enum Day extends Test{}   // compile error
20

Abstract Methods → Strategy Pattern

Each constant can supply its own body for an abstract method — a clean, built-in Strategy Pattern with no if/else chain.

Operation.java
enum Operation{

    ADD{
        public int apply(int a,int b){ return a+b; }
    },
    SUBTRACT{
        public int apply(int a,int b){ return a-b; }
    };

    public abstract int apply(int a,int b);
}
Operation.ADD.apply(10,20);

26

What the Compiler Actually Generates

you write
enum Day{ MONDAY, TUESDAY }
compiler produces
final class Day extends Enum<Day>{

    public static final Day MONDAY = new Day("MONDAY",0);
    public static final Day TUESDAY = new Day("TUESDAY",1);

    private Day(String name,int ordinal){
        super(name,ordinal);
    }
}

You never write this — the compiler generates it silently — but it's why every constant is a genuine object with a name and ordinal baked in at construction time.

Combined Example — Nearly Everything in One Enum

Constants, fields, constructor, getters, a normal method, and an overridden toString() — all in one place. (Interfaces, abstract-method strategy, and Singleton each need their own enum, per Java's rules.)

Day.java
enum Day {

    MONDAY(1, "Start of week"),
    TUESDAY(2, "Second day"),
    WEDNESDAY(3, "Middle of week");

    private int dayNumber;
    private String description;

    Day(int dayNumber, String description) {
        this.dayNumber = dayNumber;
        this.description = description;
    }

    public int getDayNumber() { return dayNumber; }
    public String getDescription() { return description; }

    public void display() {
        System.out.println(dayNumber + " : " + description);
    }

    @Override
    public String toString() {
        return "Day{dayNumber=" + dayNumber + ", description='" + description + "'}";
    }
}
Main.java
Day d = Day.MONDAY;
d = Day.TUESDAY;

System.out.println(d);                 // toString()
System.out.println(d.getDayNumber());  // 2
System.out.println(d.getDescription());// Second day
d.display();                           // 2 : Second day

for (Day day : Day.values()) System.out.println(day);

Day.valueOf("MONDAY");
Day.WEDNESDAY.ordinal();               // 2
Day.MONDAY.name();                     // MONDAY
Day.MONDAY.compareTo(Day.WEDNESDAY);    // -2
Day.MONDAY == Day.MONDAY;               // true
